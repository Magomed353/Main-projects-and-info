# Крестики-нолики — Multiplayer API

REST API на Flask для игры в крестики-нолики против компьютера или другого пользователя.

Проект развивает предыдущую версию приложения: добавляет хранение данных в PostgreSQL, регистрацию пользователей, HTTP Basic Auth и режим игры вдвоём.

## Возможности

- Регистрация пользователей с уникальными логинами и UUID.
- Аутентификация по логину и паролю через HTTP Basic Auth.
- Защита игровых маршрутов от неавторизованных запросов.
- Создание игр против компьютера или другого пользователя.
- Получение списка игр, ожидающих второго участника.
- Присоединение к существующей игре.
- Передача хода между участниками.
- Генерация ходов компьютера с помощью алгоритма «Минимакс».
- Определение победы и ничьей.
- Сохранение пользователей и состояния игр в PostgreSQL.
- Получение информации об игре и пользователе по UUID.

## Технологии

- **Python 3.10+**
- **Flask** — HTTP-маршрутизация и JSON-ответы.
- **PostgreSQL** — хранение пользователей и игр.
- **SQLAlchemy 2.x** — ORM и работа с базой данных.
- **psycopg2** — драйвер подключения к PostgreSQL.
- **HTTP Basic Auth** — аутентификация запросов.
- **Минимакс** — выбор хода компьютера.
- **uuid** — идентификаторы пользователей и игр.

## Архитектура

Приложение разделено на четыре слоя:

| Слой | Ответственность |

| `web` | HTTP-маршруты, модели запросов и ответов, проверка авторизации и преобразование данных. |

## Установка

Требуются Python 3.10+, `pip` и работающий сервер PostgreSQL.

Установите зависимости из корня проекта:

```bash
python -m pip install Flask "SQLAlchemy>=2.0,<3.0" psycopg2-binary
```

### Настройка PostgreSQL

Создайте базу данных, например:

```sql
CREATE DATABASE tictactoe;
```

В файле `src/datasource/database.py` укажите строку подключения:

```python
DATABASE_URL = "postgresql://USER:PASSWORD@localhost:5432/tictactoe"
```

Замените `USER` и `PASSWORD` на учётные данные пользователя PostgreSQL с правами на работу с этой базой.

Подключение настраивается непосредственно в файле: чтение `.env` и переменных окружения пока не реализовано.

Таблицы `users` и `games` создаются автоматически при инициализации приложения. Саму базу данных необходимо создать заранее.

## Запуск приложения

Выполните из корня проекта:

```bash
cd src
python -m web.route.controller
```

Запуск из каталога `src` необходим для корректного разрешения импортов между слоями.

Сервер разработки запускается по адресу `http://127.0.0.1:5000` с включённым режимом отладки.

Для взаимодействия с API можно использовать Postman или другой HTTP-клиент.

## Аутентификация

### Регистрация

```http
POST /signup
Content-Type: application/json
```

Пример тела запроса:

```json
{
  "login": "alice",
  "password": "example-password"
}
```

При успешной регистрации сервер возвращает HTTP-статус `201`:

```json
{
  "status": "зарегистрирован"
}
```

### Вход

```http
POST /login
Authorization: Basic <Base64(login:password)>
```

Сервер проверяет учётные данные и возвращает UUID пользователя.

В Postman выберите тип авторизации **Basic Auth** и укажите логин и пароль. Клиент сформирует заголовок автоматически.

Для каждого защищённого запроса необходимо передавать Basic Auth. Метод `/login` возвращает UUID пользователя, а не токен доступа.

## Методы API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/signup` | Регистрация пользователя. |
| `POST` | `/login` | Проверка учётных данных и получение UUID пользователя. |
| `POST` | `/game/new` | Создание игры. |
| `GET` | `/games` | Получение игр со статусом `WAITING`. |
| `POST` | `/game/{uuid}/join` | Присоединение к игре. |
| `POST` | `/game/{uuid}` | Отправка хода. |
| `GET` | `/game/{uuid}` | Получение текущего состояния игры. |
| `GET` | `/user/{uuid}` | Получение UUID и логина пользователя. |

Все игровые маршруты и получение информации о пользователе требуют Basic Auth.

## Создание игры

```http
POST /game/new
Content-Type: application/json
```

Пример игры против другого пользователя:

```json
{
  "game_type": "VS_PLAYER"
}
```

Доступные режимы:

| Значение | Режим |
| --- | --- |
| `VS_COMPUTER` | Игра против компьютера. |
| `VS_PLAYER` | Игра против другого пользователя. |

Для игры против компьютера передайте:

```json
{
  "game_type": "VS_COMPUTER"
}
```

Ответ содержит UUID игры, игровое поле, режим и начальное состояние.

## Представление игрового поля

Поле представлено целочисленной матрицей размером 3×3:

| Значение | Описание |
| --- | --- |
| `0` | Пустая клетка. |
| `1` | Отметка первого игрока. |
| `2` | Отметка второго игрока или компьютера. |

### Выполнение хода

```http
POST /game/{uuid}
Content-Type: application/json
```

Передайте полное игровое поле после своего хода:

```json
{
  "field": [
    [1, 0, 0],
    [0, 0, 0],
    [0, 0, 0]
  ]
}
```

В режиме `VS_COMPUTER` сервер выполняет ответный ход компьютера. В режиме `VS_PLAYER` передаёт очередь следующему участнику.

Ответ содержит:

| Поле | Описание |
| --- | --- |
| `uuid` | Идентификатор игры. |
| `field` | Обновлённое игровое поле. |
| `status` | Результат проверки завершения игры. |
| `current_turn` | UUID следующего игрока или `null`. |

## Состояния игры

В модели используются следующие состояния:

| Состояние | Описание |
| --- | --- |
| `WAITING` | Ожидание второго участника. |
| `PLAYER_TURN` | Очередь хода игрока. |
| `DRAW` | Ничья. |
| `PLAYER_WIN` | Победа одного из участников. |

В ответе на выполнение хода API также может вернуть `CONTINUE`, если игра продолжается.

## Пример игры вдвоём

1. Зарегистрируйте двух пользователей, например `alice` и `bob`.
2. От имени `alice` создайте игру с режимом `VS_PLAYER`.
3. От имени `bob` получите список доступных игр через `GET /games`.
4. Присоединитесь к выбранной игре через `POST /game/{uuid}/join`.
5. По очереди отправляйте обновлённое поле через `POST /game/{uuid}`, используя учётные данные соответствующего игрока.
6. Получайте состояние игры через `GET /game/{uuid}`.

## Ответы с ошибками

| HTTP-статус | Примеры причин |
| --- | --- |
| `400` | Некорректный ход, попытка ходить вне очереди, завершённая или заполненная игра. |
| `401` | Отсутствие авторизации или неверная пара логин/пароль. |
| `404` | Игра или пользователь не найдены. |
| `409` | Пользователь с таким логином уже существует. |

Для явно обработанных ошибок сервер возвращает JSON:

```json
{
  "error": "Сейчас не ваш ход"
}
```

## Хранение данных

В PostgreSQL сохраняются:

- UUID, логин и пароль пользователя.
- UUID и игровое поле каждой игры.
- Режим и состояние игры.
- Список участников и назначенные им символы.
- UUID игрока, которому принадлежит текущий ход.

Данные сохраняются между перезапусками приложения. Создание таблиц выполняется через SQLAlchemy; механизм миграций пока не добавлен.

## Ограничения текущей версии

- Пароли сохраняются и сравниваются без хеширования.
- Проверка игрового поля, принадлежности пользователя к игре и условий присоединения требует доработки.
- Согласованность сохранённого состояния игры и поля `current_turn` при выполнении ходов требует доработки.
- При победе возвращается статус `PLAYER_WIN`, но UUID победителя отдельно не сохраняется и не передаётся.
